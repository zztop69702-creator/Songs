# quality-check: 검증과 결과 보고

목표는 '되는 것 같다'가 아니라 **숫자와 캡처로 보이는 증거**다. 하지 않은 검사는 '검증하지 못함'으로 적는다.

## 1. 무엇을 검사할지 고른다 (CLAUDE.md D 목록 중 관련된 것)
| 바꾼 것 | 꼭 할 검사 |
|---|---|
| JS/HTML 코드 | 문법(훅 자동) · 페이지 오류 0 · 주요 흐름 클릭 |
| 계산식·데이터 표 | **같은 입력으로 전후 결과 비교**(차이 줄 수), 경계값(0, 최대, 빈칸) |
| 화면 배치 | PC 1366·1920, 휴대폰 390 캡처, 가로 넘침 0, 글자 겹침 |
| 저장 구조 | 옛 저장값으로 열어도 멈추지 않는지(깨진 값·빠진 필드) |
| 출력·다운로드 | 파일 형식 머리글 확인(ZIP `50 4b 03 04`, PDF `%PDF`), 한글 파일명 |
| 문서·보고서 | 숫자 합계 재계산, 단위 표기, 한글 깨짐 |

## 2. 범용 스크립트
- `scripts/html-smoke.js <html 파일> <결과 폴더>`: PC·휴대폰으로 열어 페이지 오류·콘솔 오류·앱 안 자동검사(console.assert) 실패를 모으고, 가로 넘침을 재고, 캡처를 남긴다.
- 전후 비교: 수정 전 파일을 `git show HEAD:<경로> > base.html` 로 꺼내 같은 입력으로 결과 텍스트를 뽑아 줄 단위로 비교한다(경험곱하기AI 의 `experience-ai-release/scripts/regress.js` 가 본보기).
- 앱 전용 검사가 있으면 그것을 우선한다(예: `experience-ai-release/scripts/check_all.sh`).

## 3. 증상 신고 검증
사용자 캡처의 상태를 그대로 만들고, 사용자가 누른 순서대로 누른 뒤, 각 단계의 화면 값을 표로 남긴다. 사용자가 **옛 버전**을 보는 경우가 많으니 빌드 번호나 문구로 먼저 확인한다.

## 4. 보고 형식
```
**테스트 결과**
| 검사 | 방법 | 결과 |
(예: 흐름 1~10단계 | PC·휴대폰 자동 클릭 | 오류 0건)
**기존 기능 영향:** 결과카드 비교 n줄 차이(의도한 것만)
**검증하지 못한 것:** (예: Windows 실설치, 실제 프린터 출력)
```
