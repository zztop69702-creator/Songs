# app-builder: 업무용 웹앱 개발·수정

송유성의 앱은 대부분 **설치 없이 브라우저에서 도는 한 파일 HTML 앱**이고, 일부는 Windows 설치 파일(.bat + PowerShell)로 배포한다. 사용자는 현장 기술자와 50~60대 교육생이다. 그래서 '작동한다'는 증거와 '기존 것이 그대로다'는 증거가 코드 품질보다 중요하다.

## 1. 시작 전 (항상)
1. `CLAUDE.md` 규칙과 해당 프로젝트 README 를 읽는다. 확정된 디자인·저장 키·계산 기준을 메모한다.
2. 고칠 곳을 `grep -n` 으로 찾고 앞뒤를 읽는다. 데이터 표·상태·계산 함수·화면 함수가 어디 있는지 먼저 파악한다.
3. 증상 신고면 **재현부터**: Playwright 로 같은 상태(localStorage 등)를 만들어 확인한다. 사용자가 옛 버전을 보고 있는지(빌드 번호, 문구 grep)도 확인한다.

## 2. 규모 판단
| 규모 | 예 | 처리 |
|---|---|---|
| 소 | 오타, 문구, 재현된 버그 | 바로 수정 → 검사 → 보고 |
| 중 | 기능 추가, 화면 일부 배치 | 계획 3~5줄 → 구현 → 회귀 검사 |
| 대 | 새 앱, 화면 재구성, 계산 규칙 변경 | 요구사항·MVP 범위 → **시안/설계 승인** → 단계별 개발 |

## 3. 수정 방법
- 바꾸는 문자열이 정확히 한 곳인지 확인하고 바꾼다(파이썬 `assert t.count(a) == 1` 패턴). 큰 파일을 통째로 다시 쓰지 않는다.
- 이유를 한국어 주석 한 줄로 남긴다. 데이터 표 길이 같은 불변 조건은 `console.assert` 로 둔다.
- 저장(localStorage) 키와 기존 데이터 구조는 유지한다. 새 필드는 기본값을 주고, 옛 저장값을 정리하는 `check()` 같은 함수에서 검증한다.
- 맨 위 선언 순서에 주의한다(아래쪽 `const` 를 위에서 쓰면 TDZ 오류로 앱 전체가 멈춘다).
- 새 화면은 `design-system` 규칙을 따른다(기존 앱은 기존 디자인 유지).

## 4. 반응형·접근성 기본
- 900px 이상 PC, 그 아래 위아래 배치, 620px 이하 휴대폰. 가로 넘침 0.
- 큰 글씨(기본 18px 내외)와 큰 버튼(44px 이상), 키보드 포커스 표시, 움직임 줄이기 설정 존중(필요하면 '움직임 켜기' 버튼).
- 한글은 `word-break: keep-all`. 조사(이/가, 을/를)가 바뀌는 문구는 받침 판별 함수로 처리한다.

## 5. 검증 (quality-check 스킬의 절차)
최소: 문법(훅이 자동) · 페이지 오류 0 · 주요 흐름 클릭 · PC/휴대폰 화면 · 계산 결과 전후 비교. 범용 스크립트: `.claude/skills/quality-check/scripts/html-smoke.js`.
