| 오버레이 영상 저장 | **조건부** | CameraX `OverlayEffect`(camera-effects 1.4+) 존재 [확인]. 단 VIDEO_CAPTURE 적용 불량 보고 있음 → 후처리 렌더링을 기본안으로 |

| 자동 음원탐지 — 소형 배열 | **저주파에서 사실상 불가 / 고주파에서 조건부** | 송풍기 BPF 대역(대략 100~800 Hz)은 휴대 가능한 배열 크기(≤0.5 m)로 공간분해능 확보 불가 [계산] |
| 자동 위치 표시 — **AR 스캔 히트맵 (채택, D-012)** | **조건부 추진 가능** | 근접 측정 + ARCore 위치 추적. 전 대역 적용 가능 [추정 → 실기기]. §6.7 |

**핵심 권고 (독립 판단):**
0. **[승인 반영 2026-11-10]** 아래 1번 권고는 D-012로 확정됨: 자동 위치 표시의 기본 = AR 스캔 히트맵(Phase 3A), 대형 배열 = 선택 확장(Phase 3B).
1. **AUTO 음원탐지의 적용 범위를 재정의해야 한다.** 급식실 송풍기의 주요 소음(BPF, 모터 120 Hz 등)은 저주파 순음이고, 타일·스테인리스로 둘러싸인 고반사 공간이다. 이 조건에서 소형 배열의 "음원 위치 표시"는 물리적으로 신뢰도가 낮다. AUTO는 **약 2 kHz 이상 성분**(베어링, 누기, 캐비닛 틈새, 인버터 캐리어음)에 한정하고, 저주파는 **근접 스캔(Near-field scan) 방식**으로 대체할 것을 제안한다 (§6).
2. Phase 3 장비 구매 전, **PC(또는 라즈베리파이)에서 다채널 WAV 파일 기반 알고리즘 검증**을 먼저 수행하고, Android 직결은 그 다음 단계로 미룬다.
3. 앱 결과는 영업·진단 **참고자료**로 포지셔닝하고, 법정 소음측정(작업환경측정 등)을 대체한다고 표현하지 않는다 (§8).

## 2. 마이크 입력 및 소음도

### 2.1 오디오 소스 선택
- **[확인]** Android CDD 5.11(Capture for Unprocessed)은 `UNPROCESSED` 소스를 지원한다고 선언한 기기에 대해 100 Hz~7000 Hz에서 ±10 dB 이내의 평탄도, 1 kHz·94 dB SPL 기준 입력 감도 요건을 둔다. 지원 여부는 `AudioManager.getProperty(PROPERTY_SUPPORT_AUDIO_SOURCE_UNPROCESSED)`로 확인한다.
  - 정확한 기준 출력값과 최신 조항은 source.android.com의 **현행 CDD에서 재확인 필요**.
- **[확인]** CTS Verifier에는 기준 소음계·USB 기준 마이크·외부 스피커를 사용한 Unprocessed(94 dB SPL)/Voice Recognition(90 dB SPL) 시험 절차가 있다 → 우리 기기 시험 절차의 참고 모델로 사용한다.
- **[추정]** `VOICE_RECOGNITION` 소스는 일반적으로 AGC·노이즈 억제가 비활성화된 경로지만, 기기별 차이가 있다.
- **설계 결정:** 우선순위 `UNPROCESSED` → `VOICE_RECOGNITION` → `MIC`. 사용한 소스, AGC/NS/AEC 효과 활성 여부(`AutomaticGainControl.isAvailable()` 등)를 **측정 메타데이터에 필수 기록**한다.

### 2.2 스마트폰 내장 마이크의 한계 [추정 → 실기기]
- 내장 MEMS 마이크는 저주파(약 100 Hz 이하)에서 감도 저하·하이패스 특성이 흔하다. 송풍기 회전주파수(수십 Hz)와 모터 120 Hz 대역 레벨은 과소평가될 수 있다.
- 기기마다 감도·주파수응답이 달라 **기기별 교정 오프셋 + 교정 이력**이 필수다.
- 참고: 미국 NIOSH 연구(Kardous & Shaw, JASA 2014)는 스마트폰 소음측정 앱의 정확도가 기기·앱에 따라 크게 다르며, 외장 교정 마이크 사용 시 개선됨을 보고했다. (원문 재확인 권장)

### 2.3 교정 전략
| 단계 | 방법 | 표시 라벨 |
|---|---|---|
| 미교정 | 상대 레벨(dBFS)만 | "미교정 · 상대값" — dB(A) 표기 금지 |
| 현장 비교교정 | 기준 소음계(Class 1/2)와 동일 위치·동시 측정 → 오프셋 산출 | "참고값 (기준기 비교교정 YYYY-MM-DD, 기준기 모델/S/N)" |
| 외장 교정 마이크 | 제조사 개별 교정파일(감도·주파수응답) + 음향교정기 94 dB/1 kHz 확인 | "참고값 (외장마이크 교정)" |

- 어떤 경우에도 **"공인 측정값"이 아님**을 화면·보고서에 병기한다.

### 2.4 SPEC 보완 제안 (누락 사항)
1. **시간가중 미지정:** Lmax/Lmin은 Fast(125 ms) / Slow(1 s) 중 무엇인지 지정 필요 → LAFmax/LASmax 형태로 명시. 기본 Fast 제안.
2. **C가중/Z가중 추가 제안:** LCeq − LAeq 차이는 저주파 소음 우세 여부의 간단한 지표 → 송풍기 진단에 유용.
3. **Leq 적분시간** 및 측정 시간(예: 30 s, 60 s) 규정 필요.
4. **1/3 옥타브 필터 등급**(IEC 61260-1 Class 1/2 준거 여부) — 앱은 "FFT 합성 1/3 옥타브(참고)"로 표기하고 규격 준거 주장 금지.

## 3. 주파수 분석

### 3.1 FFT 분해능 [계산, fs = 48 kHz]
| FFT 크기 N | Δf = fs/N | 프레임 길이 |
|---|---|---|
| 4096 | 11.72 Hz | 0.085 s |
| 8192 | 5.86 Hz | 0.171 s |
| 16384 | 2.93 Hz | 0.341 s |
| 32768 | 1.46 Hz | 0.683 s |

- 기본값 제안: N = 8192, Hann 윈도, 50% 오버랩. 저속 회전주파수 분석 시 16384 이상.
- 화면에 fs, N, 윈도, Δf를 항상 표시 (SPEC B항 충족).

### 3.2 회전·날개통과주파수 [계산 — 예시값]
- f_rot = N/60, f_BPF = N × Z / 60
- 예1) 1750 rpm, 12매 → f_rot = 29.2 Hz, BPF = 350 Hz
- 예2) 1200 rpm, 40매(다익 송풍기 가정) → f_rot = 20 Hz, BPF = 800 Hz
- 국내 계통 60 Hz → 모터 전자기음 기본 120 Hz(2×전원주파수) 후보. 인버터 구동 시 캐리어 주파수(수 kHz) 성분 후보. **후보 표시일 뿐 원인 확정 아님.**
- 예시 rpm·날개수는 가정값이며 실제 설비 명판/실측 rpm으로 대체해야 한다.

### 3.3 단위 혼동 방지
- FFT 스펙트럼 축은 **dBFS(상대)** 기본. 교정 상태일 때만 "dB SPL(참고)" 전환 허용.
- 소음도 위젯(dB(A))과 스펙트럼 위젯(dBFS)을 서로 다른 색·라벨로 구분.

## 4. 카메라 + 마이크 동시 처리

### 4.1 권장 아키텍처
- CameraX `VideoCapture`는 **오디오 비활성(무음 영상)** 으로 녹화.
- 측정용 오디오는 앱의 `AudioRecord`로 별도 취득 → 원본 **WAV(PCM 16/24bit 또는 float)** 저장.
- 이유: (a) CameraX 내장 오디오는 AAC 압축·전처리 경로라 측정용 부적합, (b) 같은 마이크에 대한 두 캡처 경로 동시 사용은 기기별 동작이 달라 위험 [추정], (c) "원본 보존" 원칙 충족.
- 필요 시 내보내기 단계에서 MediaMuxer로 시청용 MP4(영상+AAC) 별도 생성.

### 4.2 동기화
- 오디오: `AudioRecord.getTimestamp()`(API 24+)로 프레임 위치 ↔ `CLOCK_MONOTONIC` 시각 매핑.
- 영상: 프레임 타임스탬프 소스 `SENSOR_INFO_TIMESTAMP_SOURCE`가 `REALTIME`인지 `UNKNOWN`인지 기기별 상이 [실기기].
- 따라서 **동기 오차는 반드시 실측**: 박수/LED+비프 동시 신호를 촬영해 영상 프레임과 WAV 온셋 차이를 측정 (TEST_PLAN T-05). 목표 제안: ±1 프레임(30 fps 기준 ±33 ms) 이내, 확정은 시험 후.

### 4.3 오버레이 영상
- **[확인]** CameraX 1.4.0에서 `camera-effects` 아티팩트의 `OverlayEffect`(Canvas 기반 프레임 오버레이)가 도입됨. Preview/VideoCapture 타깃 지정 가능.
- **[확인 — 커뮤니티 보고]** Preview+VideoCapture 동시 타깃 시 녹화본에 오버레이가 적용되지 않았다는 보고, 다른 CameraEffect와 병용 시 카메라가 열리지 않았다는 보고가 있음.
- **결정 제안:** 기본은 **원본 무음 영상 + 오버레이 메타데이터(JSON) 저장 → 내보내기 시 후처리 렌더링**. `OverlayEffect` 실시간 굽기는 Phase 2에서 기기별 시험 후 선택 기능으로.

## 5. ARCore Depth 거리

- **[확인]** Depth API는 ARCore 지원 기기 중 일부만 지원하며, `Session.isDepthModeSupported(Config.DepthMode.AUTOMATIC)`로 확인한다. 기본 비활성. Raw Depth API는 정확도가 더 높지만 모든 픽셀을 채우지 않는다.
- **[확인]** ARCore의 카메라 공유는 **Camera2 API 기반 Shared Camera**로 제공된다. → **CameraX 녹화와 ARCore 세션은 동시에 같은 카메라를 쓸 수 없다**(CameraX 경로로는 공유 불가). 
- **설계 결정 제안:** "거리 측정 모드"를 별도 화면으로 분리. 사용자가 대상 표면을 탭 → ARCore hit-test/Depth로 거리 산출 → 스냅샷(이미지+거리+신뢰도) 저장 → 녹화 모드 복귀.
- **[추정]** 주방의 스테인리스·광택면, 무늬 없는 벽, 수증기·저조도에서 깊이 품질이 저하될 수 있음. 측정 실패 시 **값 생성 금지, "측정 실패" 기록**.
- 표면거리 ≠ 음원거리. 거리 레코드에 `source(AR_DEPTH/EXTERNAL_LASER/MANUAL)`, 대상점(영상 좌표), 신뢰도, 비고 필수.

## 6. 자동 음원탐지 — 물리적 한계 검토 (가장 중요)

### 6.1 파장과 배열 간격 [계산, c = 343 m/s]
| 주파수 | 파장 λ | 공간 앨리어싱 없는 최대 간격 λ/2 |
|---|---|---|
| 125 Hz | 2.74 m | 1.37 m |
| 250 Hz | 1.37 m | 0.69 m |
| 500 Hz | 0.69 m | 0.34 m |
| 1 kHz | 0.34 m | 0.17 m |
| 2 kHz | 0.17 m | 0.086 m |
| 4 kHz | 0.086 m | 0.043 m |

### 6.2 배열 크기별 빔폭(분해능) [계산, 선형배열 근사 θ₋₃dB ≈ 0.886·λ/D]
| 주파수 | 배열 폭 D = 0.2 m | D = 0.5 m | 20° 분해능에 필요한 D |
|---|---|---|---|
| 250 Hz | 분해 불가 | 분해 불가 | 약 3.5 m |
| 500 Hz | 분해 불가 | 약 70° | 약 1.7 m |
| 1 kHz | 약 87° | 약 35° | 약 0.87 m |
| 2 kHz | 약 44° | 약 17° | 약 0.44 m |
| 4 kHz | 약 22° | 약 9° | 약 0.22 m |

**해석:**
- 스마트폰에 부착 가능한 수준(≤0.2~0.5 m)의 배열로는 **1 kHz 이하에서 "어느 부위에서 소리가 나는지" 영상에 점으로 찍을 분해능이 없다.**
- 단일 우세 음원·고 SNR이면 방향 추정 정확도는 빔폭보다 좋을 수 있고(GCC-PHAT, MUSIC 등), 디컨볼루션(DAMAS, CLEAN-SC)으로 개선 여지는 있다. 그러나 급식실은 **고반사 + 저주파 순음(정재파)** 환경이라 이 이점이 크게 줄어든다 [추정 → 실기기].
- 참고: 상용 휴대형 음향카메라 상당수가 kHz 대역(누기·부분방전 탐지) 중심으로 설계되는 것도 같은 물리적 이유로 판단된다 [추정 — 제품 사양 확인 필요].

### 6.3 GCC-PHAT 시간분해능 [계산]
- fs = 48 kHz에서 1 샘플 = 경로차 7.15 mm → 간격 0.1 m 쌍에서 정면 부근 약 4.1°. 부표본 보간으로 개선 가능.
- 250 Hz, 간격 0.1 m, 90° 입사 시 채널 간 위상차 약 26° → 채널 간 위상 불일치 수 도(°)만으로도 큰 각도 오차. **채널 간 동기·위상 정합이 필수**인 이유.

### 6.4 대안 제안: 저주파용 "근접 스캔 맵" (스마트폰 단독 가능)
- 사용자가 교정된 마이크를 설비 표면 근처(예: 0.1~0.3 m)로 이동하며 지점별 레벨·대역 레벨을 기록하고, 영상 프레임에 지점 마커를 남긴다 → 대역별 레벨 맵.
- 근접장에서는 가장 가까운 음원의 기여가 우세하므로 "어디가 가장 큰가"를 실용적으로 판별 가능 [추정 — 반사·배경소음 영향 실험 필요].
- 데이터 출처는 `MEASURED`(지점 측정) + `MANUAL`(위치 지정)로 정직하게 표기되며, 배열 없이도 SPEC D항 원칙(임의 탐지 결과 생성 금지)을 지킨다.
- 더 엄밀한 방법은 2-마이크 음향인텐시티 프로브(ISO 9614 계열)이나 장비가 고가 — Phase 5 이후 검토.
- **본 제안은 SPEC 범위 변경이므로 승인 필요** (DECISIONS.md D-007, 제안 상태).

### 6.5 AUTO 모드 적용 조건 (안)
- 동기화 다채널 배열 연결 + 채널 간 동기 확인 통과 + 분석 대역 하한이 배열 크기로 정해지는 최소 주파수 이상일 때만 활성.
- 화면에 "분석 대역, 배열 크기 기준 이론 분해능, 반사 환경 경고"를 항상 표시.

### 6.6 대형 배열 (Phase 3B, 선택 확장) [계산]
- 배열 폭 D = 2 m 기준 빔폭: 500 Hz 약 17°, 250 Hz 약 35°. 1~2 m 거리에서 "어느 설비/부위군" 수준 구분 가능.
- 근거리(배열 폭과 비슷한 거리)에서는 원거리 근사가 맞지 않으므로 근거리 빔포밍 모델 적용 필요.
- 부피·비용이 크고 반사 영향이 남으므로 3A 결과로 부족할 때만 착수.

### 6.7 AR 스캔 히트맵 (Phase 3A, 채택 — D-012)
**원리:** 폰에 외장 교정 마이크를 고정하고, 설비 표면에서 약 0.1~0.3 m 거리를 1~3분간 훑는다. ARCore가 폰(=마이크)의 6자유도 위치를 추적하고, 각 위치의 대역별 레벨을 기록한 뒤 대상 표면 위에 히트맵을 생성해 영상에 자동으로 겹친다.

**적합한 이유:**
- 근접장에서는 가장 가까운 음원의 기여가 우세하여 반사음 영향이 줄어든다 [추정 → 실기기].
- 분해능이 파장이 아니라 **마이크-표면 거리와 스캔 간격**에 좌우되므로 100 Hz대 저주파에도 적용 가능 [추정 → 실기기].
- 송풍기·모터는 운전 중 정상(定常) 음원이므로 순차 스캔 방식과 잘 맞는다.
- 대역별 지도 생성 가능 (예: BPF 350 Hz 지도, 120 Hz 지도, 2~4 kHz 지도).
- 단일 프로브 + 영상 위치추적으로 표면 위 음장을 맵핑하는 상용 기법(Microflown "Scan & Paint" 계열로 알려짐)과 같은 원리 — 세부 방식은 확인 필요.

**기술 과제:**
| 과제 | 대응 | 구분 |
|---|---|---|
| ARCore 자세 시각 ↔ 오디오 시각 정렬 | 양쪽 타임스탬프를 공통 시계로 변환, 흔들기+충격음 동기 시험 | [실기기] T-16 |
| ARCore 추적 품질 (광택면·무늬 없는 면·저조도) | 추적 상태(TrackingState) 기록, 추적 상실 구간의 샘플 폐기 | [실기기] T-17 |
| 스캔 중 운전 상태 변동 | 폰 내장 마이크를 고정 기준 채널로 사용해 레벨 정규화(장시간 클럭 차이는 100 ms 단위 레벨 비교에는 영향 작음) | [추정 → 실기기] T-19 |
| 미스캔 영역 | 보간 반경 제한, 그 밖은 "미측정" 표시 (D-013) | 설계 |
| 손·몸에 의한 반사, 마이크-표면 거리 변화 | 손잡이/거치대 사용, Depth로 마이크-표면 거리 기록, 거리 범위 밖 샘플 경고 | [실기기] |
| 카메라 점유 | 스캔 중 카메라는 ARCore가 점유 → 영상은 ARCore 카메라 프레임 사용(ARCore 녹화 API 활용 여부 확인 필요) | [확인 필요] |

**데이터 표기:** 스캔 지점 레벨 = MEASURED, 보간값 = ESTIMATED, 미측정 = null.

## 7. 다채널 USB 오디오 입력

- **[확인]** Android `AudioFormat`은 API 23부터 channel index mask를 지원하며, 다채널 `AudioRecord`는 index mask 사용이 권장된다 (예: 3·4번 채널만 = 0xC).
- **[확인]** 공식 문서에 USB 입력 최대 채널 수에 대한 명시적 제한은 찾지 못함 → 반대로 **"지원 보장"도 없음**.
- **[추정]** 실제로는 기기별 USB 오디오 HAL·정책이 입력 채널 수를 2ch로 제한하거나 샘플레이트를 고정하는 사례가 보고된다. 대안으로 libusb 기반 사용자 공간 UAC 드라이버가 있으나 구현 난이도·유지보수 부담이 크다.
- **[추정]** 서로 다른 USB 마이크 여러 개(예: UMIK-1 × 4)는 **각자 독립 클럭**이라 샘플 동기가 되지 않으므로 배열 용도 부적합.
- **권장 단계:**
  1. 다채널 WAV를 PC로 녹음(멀티채널 인터페이스 또는 배열 보드) → PC/Python에서 GCC-PHAT/SRP-PHAT 검증.
  2. 통과 시 Android 후보 기기 2~3종에 배열 장치 연결 → `AudioDeviceInfo.getChannelCounts()`, 실제 index mask 녹음 채널별 독립성 확인 (TEST_PLAN T-09).
  3. Android 직결 실패 시 **보조 처리기(라즈베리파이/미니PC) 방식**: 배열 처리 결과(방향·히트맵)를 Wi-Fi로 폰에 전송, 폰은 영상·오버레이 담당. 이 경우 폰-처리기 간 시각 동기(NTP/타임스탬프 교환) 별도 검증.

## 8. 법률·사업 관점 검토 (기술 외)

### 8.1 측정값의 법적 지위 [확인 필요]
- 산업안전보건법상 **작업환경측정(소음)** 은 지정 측정기관이 규격 측정기로 수행하는 것이 원칙으로 알려져 있다. 학교 급식실 종사자 소음 노출 판단에 본 앱 값을 **공식 측정값으로 쓰면 안 된다.**
- 「환경분야 시험·검사 등에 관한 법률」의 측정기기 형식승인·정도검사, 측정대행업 등록 요건 관련: 유료 "소음 측정 서비스"를 판매하려면 등록 필요 여부를 **법률 전문가/관할기관에 확인 필요**. 설계·시공 영업의 무상 기술진단 참고자료로 쓰는 경우와 구분해야 한다.
- 최신 법령 조문은 이 문서 작성 시 **직접 확인하지 않았음.**

### 8.2 개인정보 [확인 필요]
- 학교 급식실 영상에는 조리 종사자·학생 얼굴이 찍힐 수 있다. 촬영 전 기관 승인·당사자 고지, 인물 최소 촬영, 보고서 내 얼굴 블러 처리 기능을 Phase 2 요구사항에 추가 제안.
- 영상·위치 데이터는 기기 내 저장 기본, 외부 전송 시 별도 동의.

### 8.3 공공기관 영업 시 주의
- 보고서·시연에서 "자동탐지", "정밀측정" 등 표현은 실제 검증 수준과 일치해야 하며, 장비 한계·미교정 여부를 병기한다(과장 표현은 입찰 공정성·신뢰 문제로 이어질 수 있음).
- 결과물의 작성 주체(영일)와 실제 측정 수행자를 보고서에 명기.

### 8.4 사업성 관점의 독립 의견
- **가장 높은 투자 대비 가치는 Phase 1~2**(FFT·BPF 원인 후보 제시·영상 기록·개선 전후 비교 보고서)다. 이것만으로도 "데이터로 설명하는 설비 전문가" 영업 차별화가 가능하다 [추정].
- **Phase 3(AUTO)는 고비용·고불확실성**이다. 착수 전에 (a) 상용 음향카메라 **임대 단가 견적**, (b) 실제 영업 현장에서 위치 시각화가 수주에 미친 영향을 비교하는 Go/No-Go 게이트를 둘 것을 권고한다. 가격 정보는 본 검토에서 확인하지 않았다.
