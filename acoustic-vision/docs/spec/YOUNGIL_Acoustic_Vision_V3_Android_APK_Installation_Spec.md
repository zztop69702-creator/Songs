# YOUNGIL Acoustic Vision V3.0
## Galaxy Z Fold5 직접 설치형 Android APK 개발지시서

> 승인된 개발 방향 / 아직 구현·설치 검증 전

## 문서 통제 및 승인 범위

문서명: YOUNGIL Acoustic Vision V3.0 — Galaxy Z Fold5 직접 설치형 Android APK 개발지시서

상태: 사용자 개발방향 승인 / 구현·설치·성능 검증 전

대상: Samsung Galaxy Z Fold5 (SM-F946N), 실제 Android 버전과 보안패치·정책은 기기에서 확인

목표: PC를 사용하지 않고 Claude 모바일로 개발 요청·검토하고, 클라우드 빌드된 APK를 휴대폰에서 내려받아 사용자 승인 후 설치·홈 화면에서 실행한다.

범위: 기존 소음측정·FFT·영상녹화·수동 마커·거리·스마트 소음보정 V2.0의 단계적 통합. 외장 동기화 마이크 배열 기반 자동 소음원 탐지는 후속 단계.

## 성공 기준 및 현실적 제약

성공은 APK 생성이 아니라 실제 기기에서 다운로드→설치→아이콘 실행→권한 허용→오프라인 계측→재실행→업데이트 후 데이터 보존을 검증하는 것이다.

Claude 모바일 앱 자체는 Android APK를 자동으로 빌드·무인 설치하거나 보안 승인을 대행하지 못한다. GitHub 저장소와 GitHub Actions 등 별도 클라우드 빌드 환경 및 계정 권한이 필요하다. Claude 모바일에서 저장소 수정/커밋을 직접 수행할 수 있는지는 해당 서비스 연결 및 제공 기능을 확인한다. 불가하면 스마트폰 브라우저의 GitHub 웹 편집 또는 원격 개발환경을 사용한다.

APK 사이드로딩 허용 여부는 기기 보안 정책, Auto Blocker, Android 버전, 개발자 인증 정책에 좌우된다. 보호 기능을 무조건 끄라고 안내하지 말고 공식 절차와 경고를 우선 확인한다. 사용자 승인 없이 앱 설치·권한 변경·보안설정 변경을 수행하지 않는다.

홈 화면 아이콘은 설치 후 런처에 앱이 등록되도록 구성한다. 일부 삼성 런처에서는 홈 화면 추가 조작이 필요할 수 있으므로 자동 생성은 보장하지 않는다.

## 권장 아키텍처

Android: Kotlin, Jetpack Compose, CameraX, AudioRecord/USB Audio, 로컬 데이터베이스(Room), SAF/MediaStore 내보내기. Gradle Wrapper 고정, JDK/Android SDK 버전 명시.

클라우드: 비공개 GitHub 저장소 → GitHub Actions 수동 workflow_dispatch → 빌드·단위테스트 → 서명된 APK 아티팩트 생성 → 스마트폰에서 안전하게 다운로드.

릴리스: 개발용 debug APK는 설치 시험에 한정. 실제 현장용은 고정 applicationId와 안전하게 보관된 동일 서명키를 사용하는 release APK로 배포. 개인 서명키를 저장소에 올리지 않으며 CI secrets에 안전하게 저장한다.

데이터: 앱 전용 로컬 DB 및 파일 저장소. 사용자 내보내기/백업 기능. 앱 업데이트 시 DB 마이그레이션 및 데이터 무결성 검증. 앱 삭제는 데이터 손실 가능하므로 업데이트와 재설치를 구분한다.

## 기능 우선순위와 계측의 한계

P0 설치·안정성: 실행, 권한, 카메라/마이크 동시 접근, 오프라인, 저장, 재실행, 업데이트.

P1 현장 MVP: 실시간 카메라, 단일 오디오 입력 FFT, 참고용 소음도 및 LAeq(검증 전 표기), 영상/오디오 동기화, 수동 빨간 마커, 수동 거리 입력, 프로젝트별 저장.

P2 확장: ARCore Depth 지원 검사 및 표면거리 표시, 기준 소음계 15~30초 동시 측정과 액정 OCR, 기준 LAeq 확인·보정 프로파일, PDF/CSV 보고서.

P3 별도 하드웨어: 다채널 동기화 마이크 배열·빔포밍·카메라 좌표 정합을 통한 자동 빨간 히트맵. 스마트폰 단일 마이크만으로 정확한 자동 소음원 위치를 제공한다고 주장하지 않는다.

소음계 액정 OCR 수치와 앱 LAeq는 같은 가중특성·시간구간·측정조건에서 비교한다. 순간 표시값 산술평균을 LAeq로 간주하지 않는다. 보정은 공인 교정이 아니며 음원 위치/거리 정확도를 교정하지 않는다.

## GitHub Actions 빌드 및 배포 요구사항

1. 저장소에 settings.gradle.kts, build.gradle.kts, gradle wrapper, app/src, .github/workflows/android-apk.yml, README.md, TEST_PLAN.md를 둔다.

2. workflow_dispatch로 빌드 실행; checkout, Java 설치, Gradle 빌드, 테스트, 서명, 아티팩트 업로드를 구성한다. 정확한 액션 버전과 Android SDK/Gradle 호환성은 빌드 시 검증한다.

3. 서명키 파일은 Base64 인코딩 후 CI secret으로 보관하고 비밀번호도 별도 secrets로 관리한다. 로그·아티팩트·소스에 비밀값이 출력되지 않게 한다. 최초 키 분실 시 동일 앱의 서명 업데이트가 불가능할 수 있다.

4. APK 이름에 버전명과 빌드번호를 넣고 SHA-256 체크섬 및 빌드 성공 기록을 함께 제공한다. 아티팩트 다운로드에는 GitHub 로그인 또는 유효한 접근권한이 필요할 수 있다.

5. 향후 배포는 신뢰 가능한 개인/조직 저장소 또는 공식 배포 채널을 사용하고 공개 다운로드 링크의 위·변조 위험을 관리한다.

## 스마트폰 전용 설치 절차

1. Galaxy Z Fold5의 설정 > 휴대전화 정보에서 모델명, Android 버전, 사용 가능 저장공간을 확인한다.

2. Claude 모바일에서 이 명세서를 읽고 개발 단계를 요청한다. 저장소 연결·권한이 없으면 연결 여부를 확인하고 스마트폰 브라우저로 GitHub 저장소에 접근한다.

3. GitHub Actions의 수동 빌드 실행 후 성공한 빌드의 서명된 APK 아티팩트를 스마트폰으로 다운로드한다. ZIP 아티팩트인 경우 압축을 해제한다.

4. 배포자와 체크섬을 확인한 후 APK 파일을 연다. Android가 설치 출처 허용을 요청하면 경고를 읽고 사용자가 직접 승인한다. 설치 차단 시 보안 설정·정책을 확인하고 우회 지시를 하지 않는다.

5. 앱 설치 후 실행하고 카메라·마이크 권한을 사용자가 허용한다. 앱 서랍에서 아이콘을 확인하고 홈 화면에 추가한다.

6. 비행기 모드에서 측정·영상 저장·재실행·기존 데이터 확인을 수행한다.

7. 업데이트는 동일 applicationId, 동일 서명키, 증가된 versionCode로 기존 앱 위에 설치한다. 업데이트 전 중요 데이터는 별도 내보내기한다.

## 현장 실기기 검증 및 합격 게이트

T01 다운로드: APK 파일 손상 없이 저장, SHA-256 일치.

T02 설치: 실제 Galaxy Z Fold5에서 Android 설치 성공; 실패 원인·보안 경고 기록.

T03 실행: 런처 아이콘으로 앱 실행, 비정상 종료 없음.

T04 권한: 카메라·마이크 거부/허용 모두 정상 처리, 거부 시 안내.

T05 계측: 15분 이상 연속 오디오 분석, 프레임·오디오 누락·발열·배터리 영향 기록.

T06 영상: 15분 영상녹화 후 파일 재생 및 영상·측정 시각 동기화 확인.

T07 오프라인: 비행기 모드에서 기존 로컬 기능 사용·저장.

T08 보정: OCR 오류 확인, 사용자 검토, 프로파일 저장·재실행 유지; 검증 실패 시 보정값 비활성화.

T09 거리: ARCore 미지원/깊이 취득 실패 시 수동 입력으로 전환하고 출처 표시.

T10 데이터: 앱 강제종료·재실행 시 저장자료 보존.

T11 업데이트: 동일 서명 release APK로 업데이트 후 프로젝트·영상·보정 이력 보존.

T12 실패복구: 저장공간 부족·권한철회·마이크 단절·녹화 중단 시 오류 안내와 가능한 데이터 복구.

모든 시험은 날짜, 기종, OS, APK 버전, 성공/실패, 증거 화면, 로그를 기록한다. 실제 기기 검증 전에는 '설치 검증 완료'로 보고하지 않는다.

## 개발 승인 게이트 및 Claude Code 작업 지시

PHASE 0: 현재 파일·저장소·Claude 모바일 접근방식·GitHub 권한·빌드환경·Z Fold5 설정 조사. 검증표 제출 후 사용자 승인.

PHASE 1: 설치 가능한 최소 APK(아이콘·권한·오프라인 저장·기본 UI). 실제 폰 설치 검증 후 승인.

PHASE 2: 카메라·오디오·FFT·수동 마커·녹화. 실기기 15분 시험 후 승인.

PHASE 3: AR 거리·스마트 소음보정 V2.0·보고서. 비교측정 검증 후 승인.

PHASE 4: 외장 마이크 배열 자동 음원 위치추정은 별도 사업·예산·하드웨어 승인 후 착수.

각 단계 보고: 수정파일, 빌드 명령, APK 아티팩트 위치, 실제 시험 여부, 미구현 항목, 오류 및 복구법, 다음 단계 승인 요청. 코드 작성/CI 성공만으로 설치·현장 측정 검증 완료라고 하지 말 것.
