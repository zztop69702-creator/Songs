# YOUNGIL Acoustic Vision — Claude Code 개발 지시서 V1.0

작성일: 2026-11-10  
목적: 학교 급식실 송풍기·모터·덕트·소음캐비닛의 소음도, 주파수, 음원 위치, 거리 및 영상 기록을 통합하는 Android 현장 진단 앱 개발.

## 1. 개발 의사결정
- **최종 방식:** 자동 음원탐지 + 수동 위치지정 통합형(HYBRID).
- **개발 판단:** 조건부 추진. 스마트폰 단독으로는 신뢰성 있는 음원 위치 자동탐지를 보장할 수 없음.
- **플랫폼:** Kotlin + Jetpack Compose 기반 Android 네이티브 앱.
- **핵심 원칙:** 실측 / 추정 / 수동 입력 / 시뮬레이션을 UI 및 저장 데이터에서 명확히 구분.
- **우선순위:** Phase 0 기술 검증 → Phase 1 스마트폰 MVP → Phase 2 영상·거리 → Phase 3 외장 동기화 마이크 배열 음원탐지 → Phase 4 보고서 → Phase 5 현장검증.

## 2. 요구기능
### A. 소음도
- 실시간 음압레벨 참고값, LAeq, Lmax, Lmin; A가중 처리.
- 기준 소음계 비교 교정, 장치/입력 경로/교정 이력 기록.
- AGC·노이즈 억제 등 입력 전처리 확인. 교정 전 값은 공인 dB(A)처럼 표시 금지.

### B. 주파수
- FFT 로그축, 스펙트로그램, 피크 검출, 선택 주파수대역, 1/3 옥타브 분석.
- 샘플링레이트, FFT 크기, 윈도 함수, 분해능 표시.
- 회전주파수 f=N/60, 날개통과주파수 f_BPF=N×Z/60 계산.
- FFT 상대 레벨(dBFS 등)과 음압레벨 dB SPL/dB(A) 혼동 금지.

### C. 영상 및 오버레이
- CameraX 카메라 미리보기, 영상녹화, 실시간 측정값/주파수/마커 오버레이.
- MP4, 원본 WAV, CSV/JSON, 분석 메타데이터 저장.
- 오디오와 영상은 공통 타임스탬프 기반 동기화; 저장 영상에 오버레이를 포함하는 방법 검증.
- 원본 파일은 보존하고 주석·마커 수정 내역은 별도 저장.

### D. 음원 위치
- MANUAL: 사용자가 영상에 빨간 점선 마커 지정.
- AUTO: **동기화된 다채널 마이크 배열 연결 시에만** GCC-PHAT, SRP-PHAT, 빔포밍 등으로 음원 방향/분포 추정.
- HYBRID: 자동 결과를 사용자가 수정·확정, 원래 추정값과 수정 기록 모두 저장.
- 마이크 배열이 없으면 AUTO 비활성화, 임의의 탐지 결과 생성 금지.
- 자동=빨간 실선, 수동=빨간 점선, 전문가 수정=노란색으로 구분하고 텍스트 상태 병기.
- 반사음, 다중 음원, 협대역 소음, 주파수별 공간해상도 제한 표시.

### E. 거리
- ARCore Depth 지원 기종에서 선택한 영상 표면까지 거리 측정.
- 외장 레이저 거리계 연동은 프로토콜 검증 후 구현; 수동 거리 입력 지원.
- 표면거리와 실제 음원거리는 다를 수 있으므로 거리 출처(AR/외장/수동), 대상점, 신뢰도 기록.
- AR 지원 불가/측정 실패 시 거리값 생성 금지.

### F. 현장·보고서
- 학교/현장명, 설비명, 운전조건, RPM, 날개 수, 측정 위치, 거리, 날짜, 개선 전후 구분.
- 전후 비교: 동일 운전조건/위치 여부 확인, ΔL = L_before - L_after.
- 영상 캡처, FFT, 소음도, 음원 위치, 측정조건, 제한사항을 포함한 PDF.

## 3. 하드웨어 구성 및 구매 전 확인
1. Android 스마트폰: 카메라, USB OTG, 저장용량, ARCore Depth 지원 여부 확인.
2. 외장 측정용 마이크: 감도, 주파수응답, 교정 가능 여부 확인.
3. 자동탐지용 4~8채널 이상 마이크 배열(초기 실험안): **동시 샘플링과 채널 간 시간 동기화** 필수.
4. 다채널 오디오 인터페이스/처리보드: Android에서 채널별 원시 데이터 취득 가능 여부 확인.
5. 기준 소음계, 음향 교정기, 거리 기준자/레이저 거리계, 카메라·배열 고정 프레임.
6. 마이크 배열의 개수·간격은 목표 주파수, 측정거리, 공간분해능, 반사 환경을 기준으로 선정. 구매 전 파일 기반 알고리즘 검증 수행.

## 4. 권장 소프트웨어 구조
- CameraModule: CameraX
- AudioCaptureModule: AudioRecord/USB Audio, 타임스탬프
- SoundLevelModule: 필터/레벨/교정
- FFTAnalyzerModule: FFT/스펙트로그램/피크
- SourceLocalizationModule: 다채널 방향추정/빔포밍
- DistanceModule: ARCore Depth/외장/수동
- OverlayRendererModule: 마커/히트맵/거리/수치
- RecorderModule: 영상·오디오·메타데이터 동기 저장
- MeasurementRepository: 프로젝트/측정 데이터
- ReportGenerator: PDF/CSV/JSON

## 5. 단계별 개발 및 인수기준
### Phase 0 — 기술검증 (코딩 전)
- Windows, Android Studio, JDK, SDK, Gradle, 기종/OS, 권한, USB Audio, ARCore 지원 현황 점검.
- 카메라 + 오디오 동시 취득 시험; 오디오 전처리 및 타임스탬프 확인.
- 다채널 원시 입력 가능성 및 장비 후보 비교.
- 산출물: FEASIBILITY.md, HARDWARE_MATRIX.md, RISKS.md, TEST_PLAN.md.

### Phase 1 — 스마트폰 MVP
- 카메라 미리보기, 마이크 입력, FFT, 참고용 소음도, 수동 마커, 기본 프로젝트 저장.
- 인수: 실제 입력으로 FFT 변화 확인; 마커 저장·재표시; 권한 거부/중단 처리.

### Phase 2 — 영상·거리
- MP4 녹화, 오버레이, WAV/CSV/JSON, AR 거리 또는 수동 입력, 재생·내보내기.
- 인수: 영상과 분석 시점 동기화 테스트; 지원 불가 기기 오류 처리; 거리 출처 기록.

### Phase 3 — 자동 음원탐지
- 우선 다채널 테스트 WAV로 알려진 음원 각도 검증, 다음으로 실제 배열 연동.
- 카메라-배열 좌표 보정, 방향 추정, 히트맵, HYBRID 수정 이력.
- 인수: 기준 음원 위치 대비 각도/영상좌표 오차를 시험하고 수치 기록. 합격 허용치는 장비 확정 후 별도 합의.

### Phase 4 — 보고서
- 개선 전후 비교, 주파수 그래프, 영상 캡처, 거리 출처, 교정 상태, 측정 한계 PDF 출력.
- 인수: 보고서 값이 원본 데이터와 일치하며 누락/실패 항목이 명시됨.

### Phase 5 — 현장검증
- 기준 소음계 비교, FFT 기준 신호, 음원 방향·거리 오차, 반사 환경, 장시간 안정성 시험.
- 인수: 테스트 기록과 재현 절차 확보. 공식 계측기 대체 여부는 별도 규격 검토 전 주장 금지.

## 6. 작업관리 규칙 (Claude Code 필수)
- **한 번에 전체 앱을 구현하지 말 것.** 먼저 Phase 0 문서만 작성하고 승인 대기.
- 프로젝트 루트에 README.md, DEVELOPMENT_PLAN.md, DECISIONS.md, TEST_LOG.md, CHANGELOG.md 유지.
- 기존 파일 삭제/대규모 리팩터링/새 의존성 도입 전 변경안과 영향범위 제시.
- 각 단계 종료 시: 구현기능, 테스트 명령 및 결과, 미구현/위험, 변경 파일, 다음 승인 요청 보고.
- 실제 장비 없이 실행한 시뮬레이션은 실측 검증으로 표기 금지.
- 소음원 마커의 출처(auto/manual/expert-edited), 거리 출처, 교정 상태를 데이터 모델에 필수 필드로 포함.
- UI: 네이비 #101E31, 블루 #3478F6, 빨간색 음원 마커, 모바일 가독성 우선.

## 7. Claude Code 첫 실행 명령 (그대로 입력)
당신은 Android/Kotlin, DSP, 음향 빔포밍, ARCore, 영상 동기화 개발 전문가입니다. 현재 폴더의 `YOUNGIL_Acoustic_Vision_Claude_Code_SPEC.md`를 완독하고 이를 개발 기준 문서로 사용하세요. **아직 전체 앱을 코딩하지 마세요.** 먼저 Phase 0만 수행해 개발환경, Android 기기 호환성, 카메라·마이크 동시 처리, ARCore Depth 지원, 다채널 USB 오디오 입력의 기술적 제약을 검토하세요. `FEASIBILITY.md`, `HARDWARE_MATRIX.md`, `RISKS.md`, `TEST_PLAN.md`, `DEVELOPMENT_PLAN.md`를 작성하고, 확인된 사실/추정/실기기 검증 필요를 구분해 보고하세요. 자동 음원탐지는 동기화된 마이크 배열 없이 구현됐다고 주장하지 마세요. Phase 1 착수 전 내 승인을 요청하세요.

- 우선 구매 원칙: 스마트폰 MVP 및 다채널 녹음파일 알고리즘 시험 통과 전 마이크 배열 장비 일괄 구매 보류.
