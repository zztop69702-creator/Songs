## 1. 결론

1. **V2 방향은 타당하며 Phase 1의 단순 비교교정보다 우수하다.** Phase 1의 "기준 소음계 비교" 방식은 검증구간·안전장치가 없어 V2 원칙(실패 시 자동 적용 금지)을 충족하지 못한다 → **V2 비교보정으로 대체**한다.
2. **용어 변경 권고:** 앱이 산출하는 오프셋은 KOLAS 소급 "교정"이 아니라 "보정"이다. UI·보고서에서 "비교보정"으로 표기 (V2 문서 용어와도 일치). 음향교정기(장비명)는 그대로 표기.
3. **OCR은 "입력 보조"로만 설계한다.** 기준값의 진실 근거는 ①사용자 확인값 ②원본 사진이다. 7세그먼트 LCD 숫자는 일반 문자 OCR에서 오인식(7↔1, 8↔0/6/9, 소수점 누락 72.5→725)이 잦을 것으로 예상 [추정 — 실제 소음계 화면으로 검증 필요].
4. **아래 5건은 V2 문서에 없는 보완사항으로 반영했다** (§3).

## 3. 검토 의견 및 보완 설계 (V2 문서 대비)

| # | 문제 | 근거 | 반영한 설계 |
|---|---|---|---|
| R1 | **시작 신호를 소리(비프)로 주면 보정이 오염됨.** 폰 스피커는 폰 마이크에 훨씬 가까워 앱 LAeq만 상승 | [계산] 거리 역제곱 — 폰 마이크 수 cm vs 소음계 수십 cm | 시작 신호는 **진동 + 화면 카운트다운(무음)** |
| R2 | 수동 시작 버튼으로 생기는 적분구간 어긋남 | 사람 반응시간 수백 ms [추정] | 100 ms 블록을 앞뒤 1 s 여유를 두고 기록 → **구간을 ±1 s 이동했을 때의 LAeq 변화(시간민감도)** 계산, 임계 초과 시 연장/재측정 |
| R3 | "최대 30초 연장"은 소음계도 30 s를 적분해야 의미 있음 (사후 연장 불가) | 소음계 적분은 이미 종료됨 | 연장 판정 시 **소음계·앱 모두 30 s로 재측정** 요청 |
| R4 | 보정은 단일 레벨·단일 스펙트럼 조건에서만 정확. 팬 소음(저주파 우세)과 핑크노이즈의 오프셋이 다를 수 있음 (폰 마이크 주파수응답) | [추정] | 프로파일에 **보정 음원 종류** 기록, 보고서에 "보정 조건" 표기. 다른 레벨에서 추가 검증 권장 |
| R5 | AGC 개입 여부는 API만으로 증명 불가 | FEASIBILITY §3.1 | AGC/NS 해제 실패 시 확정 금지 + 검증구간 오차로 간접 확인 |
| R6 | 많은 휴대용 소음계에 15 s Leq 프리셋이 없음 → 수동 시작/정지 | [추정 — 사용 소음계 확인 필요] | 소음계 측정시간을 사용자가 입력, 앱 구간과 ±0.5 s 초과 차이 시 확정 금지 |
| R7 | 촬영 시점 ≠ 적분구간 | V2 §5 | 사진 촬영 시각과 적분구간 시작·종료 시각을 별도 필드로 저장 |
| R8 | 휴대폰을 소음계 바로 옆에 두면 서로 차폐·반사 | V2 ② | **측정은 나란히 고정 → 측정 종료 후 폰을 들어 결과 화면 촬영**(소음계는 결과 유지) 절차 권장 |

## 4. 판정 기준 (모두 잠정값 — 기준장비 시험 후 확정, V2 §5)

| 항목 | 잠정값 | 의미 |
|---|---|---|
| 1초 LAeq 표준편차 | ≤ 1.0 dB | 초과 시 30 s 재측정, 30 s에서도 초과 시 재측정 요청 |
| 시간민감도(±1 s 이동) | ≤ 0.3 dB | 초과 시 위와 동일 |
| 간편 비교모드 변동 | 표준편차 ≤ 0.5 dB | 순간값 비교는 매우 안정된 소음에서만 |
| 검증구간 오차 | \|(앱₂+C) − 기준₂\| ≤ 1.0 dB | 합격 시 활성화 가능, 불합격 시 보류 |
| 기준값 범위 | 20 ~ 140 dB | 범위 밖은 판독 오류로 간주 |
| 구간 길이 일치 | ±0.5 s | 초과 시 확정 금지 |

## 5. 자동 확정 금지 조건 (V2 §7 → 코드 `SafetyGate`)
가중특성 ≠ A · LAeq/순간값 혼용 · 구간 불일치 · OCR 값 미확인 또는 판독 불확실 · 입력 경로 변경 · 외장 마이크 탈착(라우팅 변경) · AGC/NS 해제 실패 · 클리핑 · 기준장비 정보(모델·일련번호·교정일) 누락 · 기준값 범위 이탈 · 변동성/시간민감도 초과.

## 6. 프로파일 무효화 조건 (코드 `ProfileValidity`)
입력 장치 키 변경 · 오디오 소스 변경 · 샘플레이트 변경 · OS 빌드 변경 · 전처리 상태 변경 · 상태가 ACTIVE가 아님.
